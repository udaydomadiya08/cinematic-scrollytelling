## 1. Explain-by-showing toolkit
Exploded views; component highlighting; cross-sections and cutaways; animated assembly; input/output visualization; material and energy flow; interactive comparison (before/after, split, toggle); progressive annotation; parameter-controlled scenarios; timelines and state changes; scale ladders; zoom-through (macro to micro).

## 2. Choosing the explanatory device
- *How is it built?* -> exploded view / assembly.
- *How does it work?* -> flow diagram with moving state, cutaway, step-through.
- *Why does it matter / how big?* -> scale ladder, comparison to familiar reference.
- *What changes if...?* -> parameter control with visible consequence.
- *How did it change?* -> timeline with preserved object identity.
- *Where is it?* -> map/terrain with layered reveal.
One idea per scene. If a scene needs a paragraph to be understood, the visual is not doing its job.

## 3. Interactive models and honesty
- Every control must produce a real, internally consistent change. Do not wire sliders to decorative animation.
- Show units, ranges, and defaults. State assumptions and simplifications in plain language near the model.
- Label as **illustrative**, **simplified**, or **schematic** unless validated. Never call a toy model a "simulation" of real physics without evidence and citation.
- If numbers come from a source, cite it (title, publisher, year, link). If you estimate, say so. If you cannot verify a figure, omit or flag it.
- Prefer ranges with sources over false precision.

## 4. Data narrative structure
1. Hook: the surprising or human-scale number.
2. Context: baseline and comparison.
3. Tension: the change, gap, or anomaly.
4. Drill-down: segment, cause, mechanism.
5. Resolution: implication or action.
One insight per scene; annotate the insight directly on the chart (not only in a caption). Preserve object identity between states (bars morph, not vanish and reappear) so viewers track change.

## 5. Chart and diagram craft
- Pick encoding by task: position/length for comparison, line for trend, small multiples for many categories, map for geography; avoid pie/3D charts unless justified.
- Direct labels over legends; muted context, saturated focus.
- Start bar charts at zero; if truncating a line axis, mark it clearly.
- Use accessible color pairs; add pattern/shape when color alone carries meaning.
- Provide a data table or text summary alternative for key charts.
- Animate to reveal structure (order, grouping, change), not for flourish.
- Handle data loading, empty, and error states.

## 6. Scientific/technical integrity
- Distinguish established fact, current best estimate, and speculation; label each.
- Use correct terminology; define on first use.
- Keep scale and proportion honest; if distorted for clarity, say so ("not to scale").
- Date-stamp fast-changing facts and link to primary sources.
- Medical, legal, safety, or financial claims need qualified sources and appropriate caveats.

## 7. Scale and time devices
- Scale: logarithmic ladders with labeled orders of magnitude; zoom-through with consistent reference object.
- Time: scrubbable timeline, speed controls, clear "real time vs accelerated" label.
- Process: stages with entry/exit conditions, not just arrows.
